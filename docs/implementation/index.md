# Устройство

Родитель: [`../index.md`](../index.md).

| Модуль | Что делает |
|---|---|
| `src/tgbot_chronicle/api.py` | `BotApi`: постоянное соединение на поток, таймаут соединения 2 с на адрес и ответа 10 с, отказ сети отдельно от отказа API, журнал один раз на причину |
| `src/tgbot_chronicle/state.py` | `StateFile`: JSON под `fcntl`-замком в соседнем `.lock`, повторно входимым внутри процесса; запись через временный файл |
| `src/tgbot_chronicle/screen.py` | типы контракта и `short`/`expandable` |
| `src/tgbot_chronicle/chat.py` | `Chat`: страница, история, блок действий, маршрутизация нажатий |
| `src/tgbot_chronicle/testing.py` | `FakeTelegram` |

## Состояние

Файл, путь которого задал бот: `offset` опроса, `last_id` — последнее сообщение чата, своё или
человека; `page` — номер, экран, время последнего нажатия, флаг отложенного переезда;
`records` — записи за 8 дней и все с открытыми делами; `block` — раскрытый блок; `codes` —
короткие коды длинных данных кнопок (последние 500).

## Как нажатие находит своё место

Кнопка не несёт номера сообщения: его приносит сам `callback_query`. Нажатие страницы — это
нажатие сообщения `page.id`. Нажатие блока — сообщения `block.id`. Системные кнопки
(`~open`, `~fold`, `~back`) библиотека разбирает сама. Любое другое сообщение мёртвое: вердикт,
кнопки снимаются.

## Операция

Каждый публичный вызов `Chat` — `_operation`: замок, чтение, работа, запись, и только потом
удаление прежних страниц. Обработчик нажатия бота работает вне замка и зовёт операции сам.

## Тесты

`python3 -m unittest discover -s tests`, меньше секунды, без сети. Правила проверяются
инвариантом на подменном чате (`assert_page_last`), а не перечнем экранов.
